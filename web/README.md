# Веб-приложение (web)

Laravel 13 + Livewire (стартовый набор). Пользователи работают в браузере: шаблоны извлечения, загрузка документов, проверка и исправление результатов, экспорт. Документы обрабатывает отдельный Python-сервис (`../processor`).

## Запуск (Windows, Laravel Herd)

Нужны [Laravel Herd](https://herd.laravel.com/windows) (PHP 8.5, Composer) и Node.js. Команды — из папки `web` в PowerShell; если `php` не найден, использовать полный путь `"$env:USERPROFILE\.config\herd\bin\php.bat"`.

```powershell
composer install
npm install
npm run build
copy .env.example .env
php artisan key:generate
# в .env указать пароль PostgreSQL (DB_PASSWORD) и создать базу docextract (pgAdmin или psql)
php artisan migrate
php artisan app:create-admin        # e-mail, ФИО, пароль вводится скрыто
composer run dev                    # сервер http://localhost:8000 + сборка интерфейса
```

До установки PostgreSQL можно работать на SQLite: `DB_CONNECTION=sqlite` в `.env` (файл `database/database.sqlite`).

Сервис обработки запускается отдельно на порту 8001 (см. `../processor/README.md`); адрес и токен — `PROCESSOR_URL` и `PROCESSOR_API_TOKEN` в `.env` (токен тот же, что `PROCESSOR_API_TOKEN` в `processor/.env`).

## Тесты

```powershell
php artisan test        # SQLite в памяти, рабочая база не затрагивается
vendor/bin/pint --test  # стиль кода
vendor/bin/phpstan analyse
```

Те же тесты на PostgreSQL (jsonb, блокировки) — в отдельной базе `docextract_test`, рабочая `docextract` не затрагивается:

```powershell
$env:DB_CONNECTION='pgsql'; $env:DB_DATABASE='docextract_test'; php artisan test
```

Обращения к сервису обработки в тестах подменены (`Http::fake`), сервис запускать не нужно. Контракт с сервисом проверяют общие фикстуры `tests/Fixtures/*.json`: их читают и тесты веб-приложения, и `processor/tests/test_web_contract.py`.

## Роли

| Роль | Возможности |
|---|---|
| Пользователь (`user`) | свои шаблоны и системные шаблоны, загрузка документов, проверка и исправление результатов, экспорт, история своих документов |
| Администратор (`admin`) | всё, что пользователь, а также пользователи и роли, блокировка, системные шаблоны и типы документов, журнал действий |

- При регистрации выдаётся роль «пользователь»; роль и блокировку нельзя задать через формы — только администратор (или `php artisan app:create-admin`).
- Заблокированный пользователь (`users.is_active = false`) не может войти, а уже открытая сессия завершается на следующем запросе.
- Раздел `/admin` — только для администраторов (иначе 403).

## Шаблоны

Раздел «Шаблоны» (`/templates`): какие поля извлекать из документа.

- **Системные шаблоны** для четырёх типов документов создаются миграцией из `database/data/system_templates.json`. Это те же шаблоны, на которых измерено качество извлечения (`../processor/evaluation/templates.py`); их совпадение проверяет тест `processor/tests/test_web_system_templates.py`. Системные шаблоны видят все, меняет только администратор.
- **Свои шаблоны** пользователь создаёт с нуля или копирует системный и настраивает. Чужие личные шаблоны не видны никому, в том числе администратору.
- **Поле шаблона:** название, системное имя (ключ в результате), тип данных, обязательность, слова-якоря (по одному на строку, `*` в конце — любое окончание), подсказка для LLM, регулярное выражение (RE2), сущность NER и правила проверки значения (диапазон суммы или даты, длина, допустимые значения, формат). Нарушение правила не удаляет значение, а помечает поле «требует проверки».
- Проверки формы повторяют схему шаблона сервиса обработки (`../processor/app/schemas.py`), поэтому сохранённый шаблон сервис принимает. Поле с регулярным выражением (или форматом значения) дополнительно проверяет сам сервис (`POST /templates/validate`): только он знает, уложится ли выражение RE2 в предел сложности (например, `\pL+` — нет, для кириллицы — `[А-Яа-яЁё]`). Если сервис недоступен, такое поле не сохраняется; поля без регулярных выражений сохраняются без обращения к сервису.
- Шаблон без полей сохранить можно, но обработать им документ нельзя — в списке он помечен «нет полей».
- Ограничения: до 100 полей в шаблоне, до 20 полей с регулярным выражением, до 100 своих шаблонов и до 2000 полей во всех шаблонах пользователя; не больше 60 изменений шаблонов в минуту. Пределы проверяются в транзакции с блокировкой, параллельные запросы их не обходят.
- Изменения системных шаблонов (создание, правка, поля, удаление) пишутся в журнал действий: они затрагивают всех пользователей.
- Чужой личный шаблон для пользователя не существует: ответ 404, а не 403, чтобы нельзя было перебором узнать занятые номера.
- Удаление шаблона не удаляет обработанные документы: они остаются в истории без привязки к шаблону.

## База данных

Таблицы соответствуют схеме `../схемы/5_схема_базы_данных.drawio`: `roles`, `users`, `audit_log`, `document_types`, `templates`, `template_fields`, `documents`, `extraction_results`, `extracted_values`, `exports`. Роли и четыре типа документов (счёт, акт, договор, резюме) создаются миграциями.

Отличия от схемы (соглашения Laravel и то, что потребовалось для связи с сервисом обработки):

| Таблица | В схеме | В приложении | Зачем |
|---|---|---|---|
| users | `full_name`, `password_hash` | `name`, `password` | соглашения Laravel (хранится хеш bcrypt) |
| template_fields | — | `keywords` (jsonb), `validation` (jsonb) | слова-якоря и правила проверки поля, как в шаблоне сервиса обработки |
| documents | — | `size_bytes`, `sha256` | размер файла и контроль повторной загрузки |
| extraction_results | `error_message` | + `error_code`, `needs_review`, `warnings` (jsonb), `ocr_pages` | коды ошибок и предупреждений сервиса, статус «требует проверки», OCR |
| extracted_values | — | `field_name`, `original_value`, `raw`, `start_offset`, `end_offset`, `needs_review`, `issues`, `alternatives` | результат не зависит от последующих правок шаблона; исходное значение при ручном исправлении; подсветка в тексте; причины проверки |

Внешние ключи проиндексированы (PostgreSQL не делает этого сам). Удаление пользователя удаляет его шаблоны и документы, записи журнала остаются без привязки к пользователю; удаление шаблона не удаляет историю обработанных документов.

## Безопасность

- Вход: e-mail без учёта регистра; одинаковое время ответа для существующего и несуществующего e-mail; лимиты — 5 попыток в минуту на e-mail и IP и 20 в минуту на IP.
- Регистрация — не больше 10 в час с одного IP, запрос сброса пароля — 5 в час; ответ на сброс пароля не выдаёт, зарегистрирован ли e-mail.
- Смена e-mail — только с текущим паролем; после смены пароля завершаются сессии на других устройствах; последний администратор не может удалить свою учётную запись.
- Журнал действий (`audit_log`): вход, выход, неудачные попытки, попытки входа заблокированных, регистрация, выдача прав администратора. Хранится IP (персональные данные) — записи старше `AUDIT_RETENTION_DAYS` (365) удаляются ежедневно (`php artisan schedule:work` или планировщик Windows для `php artisan schedule:run`).
- Для продакшена: `APP_ENV=production`, `APP_DEBUG=false`, `SESSION_SECURE_COOKIE=true`; за обратным прокси — настроить доверенные прокси (`trustProxies`), иначе в журнал попадёт адрес прокси.
