# Веб-приложение (web)

Laravel 13 + Livewire (стартовый набор). Пользователи работают в браузере: шаблоны извлечения, загрузка документов, проверка и исправление результатов, экспорт. Документы обрабатывает отдельный Python-сервис (`../processor`).

## Запуск (Windows, Laravel Herd)

Нужны [Laravel Herd](https://herd.laravel.com/windows) (PHP 8.5, Composer) и Node.js. Команды — из папки `web` в PowerShell; если `php` не найден, использовать полный путь `"$env:USERPROFILE\.config\herd\bin\php.bat"`.

```powershell
composer install
npm install
npm run build
copy .env.example .env
php artisan key:generate
# в .env указать пароль PostgreSQL (DB_PASSWORD) и создать базу docextract (pgAdmin или psql)
php artisan migrate
php artisan app:create-admin        # e-mail, ФИО, пароль вводится скрыто
composer run dev                    # сервер http://localhost:8000 + сборка интерфейса
```

До установки PostgreSQL можно работать на SQLite: `DB_CONNECTION=sqlite` в `.env` (файл `database/database.sqlite`).

Сервис обработки запускается отдельно на порту 8001 (см. `../processor/README.md`); адрес и токен — `PROCESSOR_URL` и `PROCESSOR_API_TOKEN` в `.env` (токен тот же, что `PROCESSOR_API_TOKEN` в `processor/.env`).

## Главная

После входа — сводка по своим документам (обработано, требуют проверки, в очереди и с ошибкой, доступно шаблонов) со ссылками на отфильтрованный список, кнопки «Загрузить документы» и «Новый шаблон» и пять последних документов.

## Язык интерфейса

Интерфейс на русском (`APP_LOCALE=ru`): страницы стартового набора (вход, регистрация, восстановление пароля, настройки), меню, сообщения проверки форм (`lang/ru/validation.php` — все правила Laravel и названия полей), постраничный вывод, письмо со ссылкой сброса пароля (`lang/ru.json`). Время показывается в часовом поясе `APP_DISPLAY_TIMEZONE`, размеры файлов — в КБ и МБ. Тест `LocalizationTest` проверяет, что у каждой строки интерфейса из шаблонов есть русский перевод.

## Тесты

```powershell
php artisan test        # SQLite в памяти, рабочая база не затрагивается
vendor/bin/pint --test  # стиль кода
vendor/bin/phpstan analyse
```

Те же тесты на PostgreSQL (jsonb, блокировки) — в отдельной базе `docextract_test`, рабочая `docextract` не затрагивается:

```powershell
$env:DB_CONNECTION='pgsql'; $env:DB_DATABASE='docextract_test'; php artisan test
```

Обращения к сервису обработки в тестах подменены (`Http::fake`), сервис запускать не нужно. Контракт с сервисом проверяют общие фикстуры `tests/Fixtures/*.json`: их читают и тесты веб-приложения, и `processor/tests/test_web_contract.py`.

## Роли

| Роль | Возможности |
|---|---|
| Пользователь (`user`) | свои шаблоны и системные шаблоны, загрузка документов, проверка и исправление результатов, экспорт, история своих документов |
| Администратор (`admin`) | всё, что пользователь, а также пользователи и роли, блокировка, системные шаблоны, журнал действий |

- При регистрации выдаётся роль «пользователь»; роль и блокировку нельзя задать через формы — только администратор (или `php artisan app:create-admin`).
- Заблокированный пользователь (`users.is_active = false`) не может войти, а уже открытая сессия завершается на следующем запросе.
- Раздел `/admin` — только для администраторов (иначе 403); права проверяются и при каждом действии на странице (если права сняли в другой вкладке — 403).
- **Пользователи** (`/admin`): сводка (пользователи, обработанные документы, очередь, загрузки за неделю), поиск по ФИО и e-mail, число документов у каждого — без имён файлов и содержимого. Действия: заблокировать (пользователь сразу выходит со всех устройств — удаляются его сессии), разблокировать, выдать или снять права администратора. Над собой эти действия недоступны; последнего активного администратора нельзя заблокировать или лишить прав; заблокированного нельзя сделать администратором (сначала разблокировать). Проверки идут под блокировкой строк в одном порядке — два администратора не снимут права друг с друга одновременно, а права действующего администратора перепроверяются в той же транзакции. Каждое изменение пишется в журнал (повторный щелчок без изменения — нет).
- **Журнал действий** (`/admin/audit`): вход и выход (с IP), неудачные попытки, регистрация, права и блокировки, загрузка, скачивание и выгрузка документов, исправления значений, изменения системных шаблонов. Фильтры: действие, пользователь, период. Значений полей и содержимого документов в журнале нет — только идентификаторы.

## Шаблоны

Раздел «Шаблоны» (`/templates`): какие поля извлекать из документа.

- **Системные шаблоны** для четырёх типов документов создаются миграцией из `database/data/system_templates.json`. Это те же шаблоны, на которых измерено качество извлечения (`../processor/evaluation/templates.py`); их совпадение проверяет тест `processor/tests/test_web_system_templates.py`. Системные шаблоны видят все, меняет только администратор.
- **Свои шаблоны** пользователь создаёт с нуля или копирует системный и настраивает. Чужие личные шаблоны не видны никому, в том числе администратору.
- **Поле шаблона:** название, системное имя (ключ в результате), тип данных, обязательность, слова-якоря (по одному на строку, `*` в конце — любое окончание), подсказка для LLM, регулярное выражение (RE2), сущность NER и правила проверки значения (диапазон суммы или даты, длина, допустимые значения, формат). Нарушение правила не удаляет значение, а помечает поле «требует проверки».
- Проверки формы повторяют схему шаблона сервиса обработки (`../processor/app/schemas.py`), поэтому сохранённый шаблон сервис принимает. Поле с регулярным выражением (или форматом значения) дополнительно проверяет сам сервис (`POST /templates/validate`): только он знает, уложится ли выражение RE2 в предел сложности (например, `\pL+` — нет, для кириллицы — `[А-Яа-яЁё]`). Если сервис недоступен, такое поле не сохраняется; поля без регулярных выражений сохраняются без обращения к сервису.
- Шаблон без полей сохранить можно, но обработать им документ нельзя — в списке он помечен «нет полей».
- Ограничения: до 100 полей в шаблоне, до 20 полей с регулярным выражением, до 100 своих шаблонов и до 2000 полей во всех шаблонах пользователя; не больше 60 изменений шаблонов в минуту. Пределы проверяются в транзакции с блокировкой, параллельные запросы их не обходят.
- Изменения системных шаблонов (создание, правка, поля, удаление) пишутся в журнал действий: они затрагивают всех пользователей.
- Чужой личный шаблон для пользователя не существует: ответ 404, а не 403, чтобы нельзя было перебором узнать занятые номера.
- Удаление шаблона не удаляет обработанные документы: они остаются в истории без привязки к шаблону.

## Документы

Раздел «Документы» (`/documents`): загрузка и статусы обработки.

- Загрузка до 10 файлов за раз: PDF, DOCX, PNG, JPG до 20 МБ (`DOCUMENTS_MAX_FILE_MB`). Формат определяется по содержимому файла (сигнатуре), а не только по расширению; сервис обработки проверяет файл ещё раз и подробнее.
- Файлы хранятся на отдельном диске `documents` (`storage/app/private/documents/<id пользователя>/<uuid>.<формат>`) и не раздаются по ссылке. Имя файла пользователя — только для показа (без пути, управляющих символов и символов переворота текста). Удаление документа удаляет файл, удаление пользователя — всю его папку.
- Обработка — в очереди (`ProcessDocument`): файл и шаблон отправляются в сервис (`POST /extract`), результат с текстом документа (для подсветки на шаге 4) сохраняется в `extraction_results` и `extracted_values`. Сервис недоступен или перегружен — до 3 попыток с паузами 10 и 30 с; документ отклонён (защищён паролем, повреждён) — сразу «Ошибка» с причиной от сервиса. Документ с ошибкой можно отправить повторно; каждая обработка — новая запись результата (история). Повторная доставка задания (сбой обработчика) уже обработанный документ не трогает — второй отправки в сервис и LLM нет.
- Сроки согласованы: HTTP-запрос 120 с < `$timeout` задания 180 с < `retry_after` очереди 240 с (`DB_QUEUE_RETRY_AFTER`) < блокировка уникальности 600 с. Иначе долгую обработку взял бы второй обработчик.
- В сервис уходит не имя файла пользователя (в нём может быть ФИО), а `document.<формат>`.
- **Согласие на LLM** — флажок «Использовать LLM» на каждую загрузку, по умолчанию выключен: только с ним фрагменты документа уходят в GigaChat; выбор записывается в журнал действий. `DOCUMENTS_LLM_ENABLED=false` отключает LLM для всех.
- **Квоты пользователя:** до 1000 документов и 2 ГБ файлов (`DOCUMENTS_MAX_PER_USER`, `DOCUMENTS_MAX_STORAGE_MB_PER_USER`); не больше 30 файлов в минуту, пакет, который не помещается в остаток минуты, не принимается целиком.
- **Сроки хранения (152-ФЗ):** документы старше `DOCUMENTS_RETENTION_DAYS` (365) удаляются вместе с файлами и результатами (`model:prune`, ежедневно); брошенные временные загрузки (`livewire-tmp`) — через час (`app:prune-temporary-uploads`, ежечасно). Для расписания нужен `php artisan schedule:work` (или планировщик Windows для `schedule:run`).
- Пока документы в очереди или в обработке, список обновляется сам каждые 5 с.

Для обработки нужны запущенные сервис обработки и обработчик очереди: `composer run dev` запускает и сервер, и очередь; отдельно — `php artisan queue:work`. В продакшене обязателен `PROCESSOR_API_TOKEN` (без него приложение не обратится к сервису).

### Результат обработки

Страница документа (`/documents/{id}`, переход по имени файла в списке):

- **Поля:** значение в привычном виде (15 000,00 ₽, 01.03.2025), источник (правила, NER, LLM), уверенность. Поля «требует проверки» выделены, с причинами на русском (низкая уверенность, вне диапазона, значение от LLM не найдено в тексте и т. п.); если сервис нашёл несколько кандидатов — кнопки «Другие варианты».
- **Текст документа** с подсветкой найденных значений по позициям от сервиса: зелёным — уверенные, жёлтым — требующие проверки; щелчок по названию поля прокручивает текст к значению. Весь текст экранируется; длинный документ показывается до 100 тыс. символов (страница перерисовывается после каждого действия).
- **Проверка и исправление:** «Исправить» / «Ввести» — значение приводится к тому же виду, что у сервиса (дата → ГГГГ-ММ-ДД, сумма → 15000.00, ИНН — с контрольной суммой, телефон → +7…); «Верно» — снять пометку без изменения; «Значения нет» — сервис нашёл лишнее (например, «Без НДС»); «Вернуть найденное» — отменить исправление. Исходное значение сервиса сохраняется (`original_value`), документ перестаёт «требовать проверки», когда проверены все поля. В журнал действий пишутся только идентификаторы, без значений.
- **Исходный файл** — скачивание только владельцем, всегда как вложение.
- Предупреждения сервиса (LLM недоступна, OCR не распознал страницы и т. п.) показываются над полями.
- **История обработки:** если документ обрабатывался несколько раз (повтор после ошибки), под полями — список попыток с датой и причиной ошибки.

### История и выгрузка

- **Фильтры списка** (сохраняются в адресной строке): имя файла (подстрока; `%` и `_` — обычные символы), шаблон, статус, «только требующие проверки», период загрузки (даты — в часовом поясе пользователя). Неподходящие значения в адресе (чужой шаблон, неизвестный статус, несуществующая дата) игнорируются.
- **Выгрузка документа** — кнопки CSV и JSON на странице результата. CSV — строка на поле: название, значение, требует ли проверки, исправлено ли вручную, источник, уверенность.
- **Выгрузка выборки** — кнопки под фильтрами, с теми же фильтрами; только обработанные документы, до 1000 за раз (`DOCUMENTS_MAX_EXPORT`). CSV — строка на документ и столбец на поле шаблона, поэтому для CSV нужно выбрать шаблон; JSON — без ограничения по шаблону.
- CSV — UTF-8 с BOM и разделителем «;»: открывается в Excel с русской локалью без настройки. Ячейки, начинающиеся с `=`, `+`, `-`, `@`, экранируются апострофом — значение из документа не выполнится в Excel как формула; простые числа (`-5`, `15000.00`) остаются числами.
- Выборка читается и отправляется порциями по 200 документов — память не растёт с размером выгрузки. Если документов больше предела, вместо кнопок — подсказка уточнить фильтр.
- Не больше 10 выгрузок в минуту на пользователя. Каждая выгрузка записывается в `exports` (по результату) и в журнал действий.

**Размер загрузки в PHP.** В Herd по умолчанию `upload_max_filesize = 2M`: файлы больше 2 МБ не дойдут до приложения. Herd → PHP → настройки версии 8.5 → «Max file upload size» = 25 МБ (или `upload_max_filesize = 25M` и `post_max_size = 30M` в `%USERPROFILE%\.config\herd\bin\php85\php.ini`).

## База данных

Таблицы соответствуют схеме `../схемы/5_схема_базы_данных.drawio`: `roles`, `users`, `audit_log`, `document_types`, `templates`, `template_fields`, `documents`, `extraction_results`, `extracted_values`, `exports`. Роли и четыре типа документов (счёт, акт, договор, резюме) создаются миграциями.

Отличия от схемы (соглашения Laravel и то, что потребовалось для связи с сервисом обработки):

| Таблица | В схеме | В приложении | Зачем |
|---|---|---|---|
| users | `full_name`, `password_hash` | `name`, `password` | соглашения Laravel (хранится хеш bcrypt) |
| template_fields | — | `keywords` (jsonb), `validation` (jsonb) | слова-якоря и правила проверки поля, как в шаблоне сервиса обработки |
| documents | — | `size_bytes`, `sha256` | размер файла и контроль повторной загрузки |
| extraction_results | `error_message` | + `error_code`, `needs_review`, `warnings` (jsonb), `ocr_pages` | коды ошибок и предупреждений сервиса, статус «требует проверки», OCR |
| extracted_values | — | `field_name`, `original_value`, `raw`, `start_offset`, `end_offset`, `needs_review`, `issues`, `alternatives` | результат не зависит от последующих правок шаблона; исходное значение при ручном исправлении; подсветка в тексте; причины проверки |

Внешние ключи проиндексированы (PostgreSQL не делает этого сам). Удаление пользователя удаляет его шаблоны и документы, записи журнала остаются без привязки к пользователю; удаление шаблона не удаляет историю обработанных документов.

## Безопасность

- Вход: e-mail без учёта регистра; одинаковое время ответа для существующего и несуществующего e-mail; лимиты — 5 попыток в минуту на e-mail и IP и 20 в минуту на IP.
- Регистрация — не больше 10 в час с одного IP, запрос сброса пароля — 5 в час; ответ на сброс пароля не выдаёт, зарегистрирован ли e-mail.
- Смена e-mail — только с текущим паролем; после смены пароля завершаются сессии на других устройствах; последний администратор не может удалить свою учётную запись.
- Журнал действий (`audit_log`): вход, выход, неудачные попытки, попытки входа заблокированных, регистрация, выдача прав администратора. Хранится IP (персональные данные) — записи старше `AUDIT_RETENTION_DAYS` (365) удаляются ежедневно (`php artisan schedule:work` или планировщик Windows для `php artisan schedule:run`).
- Для продакшена: `APP_ENV=production`, `APP_DEBUG=false`, `SESSION_SECURE_COOKIE=true`; за обратным прокси — указать его адреса в `TRUSTED_PROXIES`, иначе в журнал и лимиты попадёт адрес прокси (без настройки заголовок `X-Forwarded-For` не учитывается и подделать адрес нельзя).
